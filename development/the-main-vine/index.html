The Main Vine

Giant pumpkin growers choose next year’s seeds by pedigree, but the weigh-off results only list each fruit’s parents as hand-typed names like “2365 Wolf 2021.” The Main Vine links every result since 2005 into family trees you can search and explore.

The problem

The Great Pumpkin Commonwealth (GPC) publishes every weigh-off as a table: weight, grower, site, and the seed and pollinator written as text. To trace a winning pumpkin back through its family, a grower has to search for each parent by name, one year at a time.

  • Parents are typed by hand. “2020 Paton” might mean one fruit, two fruits, or a misspelling of “2020 Patton.”
  • A pollinator name hides half the story. It says which seed the pollen plant grew from, not what that plant produced.
  • It isn’t only pumpkins. Eight classes, from Atlantic Giant pumpkins to tomatoes, marrows and long gourds.

Turning typed names into links

A scraper loads the published results into Postgres. Each seed and pollinator name is matched to a weighed fruit by weight, grower surname and year, allowing for small misspellings and missing years.

  • A name that fits exactly one fruit becomes a link.
  • A name that fits several is shown as “needs review,” with every candidate, and drawn with a dashed line in the tree.
  • A name that isn’t found, because the fruit is older than 2005 or was never weighed at a GPC site, stays as plain text.

For the pollinator, the site looks at the same grower’s other fruit that season. If exactly one grew from the pollinator seed, that is almost certainly the plant the pollen came from, and the tree shows what it grew. The site says plainly that these are strong hints, not certainties.

The family tree

The family tree is the main part of the site, and I drew it without a charting library. Each fruit is a real HTML card with links and buttons, positioned absolutely; the connecting lines are thin elements placed from the same coordinates.

The layout is one recursive pass. Parents are placed first, top to bottom, and each fruit is then centered on its first and last parent, so the tree never overlaps however unevenly it branches:

const place = (n, top) => {
  n.h = heightOf(n);
  n.x = colX(n.gen);
  if (n.gen > maxGen) maxGen = n.gen;
  const gap = isCompact(n) ? CGAP : GAP;
  let bottom;
  if (!n.kids.length) { n.y = top; bottom = top + n.h + gap; }
  else {
    let t = top;
    n.kids.forEach((k) => { t = place(k, t); });
    const first = n.kids[0], last = n.kids[n.kids.length - 1];
    const mid = ((first.y + anchorOf(first)) + (last.y + anchorOf(last))) / 2;
    n.y = Math.max(top, mid - anchorOf(n));
    bottom = Math.max(t, n.y + n.h + gap);
  }
  flat.push(n);
  return bottom;
};
  • Show 2 to 8 generations, or open and close any branch on its own.
  • Fold repeated ancestors: a famous seed that appears many times in a tree is drawn once and marked ×N.
  • From the fourth generation back, cards shrink to one line, so a deep tree stays readable.
  • Two ways to show what each pollinator plant grew. The choice is saved in localStorage.
  • Drag the empty part of the tree to move around it, like a map. Pointer Events with pointer capture keep the drag smooth, and buttons and links inside the tree still work.

Working out inbreeding

Every fruit page shows its inbreeding coefficient, how many generations are on record, and how many distinct ancestors. The coefficient is the kinship of the fruit’s two parents, and kinship is defined recursively: the kinship of two fruits is the average kinship of the younger one’s parents with the older one. Memoizing each pair keeps a 13-generation tree fast.

const kin = (a, b) => {
  if (a == null || b == null) return 0;
  if (!N[a] || !N[b]) return a === b ? 0.5 : 0;
  const key = a < b ? a + '|' + b : b + '|' + a;
  if (memo[key] !== undefined) return memo[key];
  let r;
  if (a === b) { const pp = par(a); r = 0.5 * (1 + (pp ? kin(pp[0], pp[1]) : 0)); }
  else {
    let x = a, y = b;
    if (N[b].y > N[a].y) { x = b; y = a; }
    const pp = par(x);
    r = pp ? 0.5 * (kin(pp[0], y) + kin(pp[1], y)) : 0;
  }
  memo[key] = r;
  return r;
};

The API

  • One Vercel Function, /api/v1, answers six questions: meta, top, fruit, search, grower and results. It queries Neon Postgres through its serverless driver.
  • Responses use the short field names the front end reads directly, which keeps payloads small for a 65,000-row dataset.
  • The front end caches each request by its query string and drops failed ones, so going back is instant and a retry actually retries.
  • Hash routes give every fruit, grower, year and search its own address, so a grower can share a link to a pedigree and the Back button works.
